Pendahuluan

KLATOS adalah sistem operasi desktop modern yang dibangun sebagai sebuah platform terpadu untuk perangkat komputasi modern.

KLATOS menggabungkan kernel, runtime, desktop, filesystem, application platform, developer tools, security model, dan application ecosystem dalam satu arsitektur yang dirancang secara terintegrasi.

KLATOS tidak hanya menyediakan lingkungan untuk menjalankan program. KLATOS dibangun sebagai platform tempat sistem, aplikasi, dan developer bekerja dalam satu model yang sama.

Setiap lapisan mempunyai tanggung jawab sendiri, tetapi seluruhnya dirancang agar dapat bekerja sebagai satu platform.

Key Facts

  • Kernel, runtime, desktop, dan aplikasi dalam satu arsitektur terintegrasi
  • KlatLoader sebagai runtime loader native
  • Filesystem root /Sistem
  • Desktop KlatDE / Nawolo
  • Application platform dengan format .kap
  • Dukungan pengembangan aplikasi native dengan Rust
  • Security model berbasis Capability Security dengan nama (Klat Security Manager (KSM))
  • Dukungan Firefox modern secara bertahap

Filosofi

Modern Architecture

Seluruh subsistem menggunakan arsitektur modern berbasis object-oriented dan event-driven sehingga setiap komponen memiliki tanggung jawab yang jelas, mudah dipelihara, dan dapat dikembangkan secara independen.

Performance First

Seluruh jalur kritis dirancang untuk meminimalkan overhead:

  • Zero-copy Virtual Memory Object (VMO)
  • Event-driven WaitQueue
  • Non-blocking I/O
  • Shared Memory IPC
  • DRM Dumb Buffer
  • Page Flipping

POSIX Compatibility

KLATOS mengimplementasikan antarmuka POSIX sehingga berbagai aplikasi dan pustaka dapat dipindahkan dengan perubahan seminimal mungkin.

Clean Architecture

Kernel tidak dibangun dari kumpulan patch, tetapi menggunakan desain modular yang memiliki batas antarsubsistem yang jelas.

Manajemen Proses

JowoKernel mengelola proses dan thread dengan fitur lengkap:

  • Multi-process Scheduler
  • Multi-thread Scheduler
  • Context Switching
  • Process Groups
  • Sessions & Job Control
  • Signal Delivery
  • Process Waiting
  • Orphan Process Handling
  • Zombie Process Management

Manajemen Memori

Sistem manajemen memori JowoKernel:

  • Physical Memory Manager (PMM) — mengelola alokasi frame fisik
  • Virtual Memory Manager (VMM) — mengelola page table dan mapping
  • Kernel Heap — alokasi memori dinamis untuk kernel
  • Slab Allocator — alokasi efisien untuk objek berukuran kecil
  • Virtual Memory Object (VMO) — abstraksi zero-copy untuk mapping
  • Memory Mapping — mmap/munmap untuk userspace
  • Shared Memory — IPC berbasis shared memory
  • Guard Pages — deteksi stack overflow
  • Copy-on-Write ready infrastructure

Filesystem

Virtual File System (VFS) dan filesystem kernel yang tersedia:

  • Virtual File System (VFS) — layer abstraksi untuk semua filesystem
  • TmpFS — filesystem berbasis RAM untuk file sementara
  • ProcFS — filesystem virtual untuk informasi proses
  • DeviceFS — filesystem untuk device nodes
  • File Descriptor Table
  • Symbolic Links & Hard Links
  • Permission Management
  • Path Resolution

Struktur filesystem tingkat sistem KLATOS dibahas pada bagian Filesystem KLATOS.

IPC (Inter-Process Communication)

Implementasi IPC menggunakan Unix Domain Socket modern:

  • Pipes
  • Unix Domain Socket (AF_UNIX)
  • Socket Pair
  • Stream Socket
  • Non-blocking Socket
  • Shared Memory Transfer
  • Zero-copy Buffer Sharing
  • File Descriptor Passing (SCM_RIGHTS)
  • Epoll Integration

Event Infrastructure

Salah satu perubahan arsitektur terbesar pada JowoKernel adalah transisi menuju model event-driven. Setiap objek filesystem memiliki WaitQueue internal.

Objek seperti Pipe, Unix Socket, Terminal, DRM Device, dan Input Device dapat membangunkan thread hanya ketika status benar-benar berubah. Pendekatan ini menghilangkan polling periodik yang memboroskan CPU.

// Event-driven pattern
waitqueue_wait(&obj->wq, &ctx);
// Thread sleeps until event occurs
// No polling, no busy-waiting

KlatLoader

Program native KLATOS dijalankan melalui KlatLoader — runtime loader sistem yang berada pada:

/Sistem/Runtime/KlatLoader.so

Ketika sebuah executable native dijalankan, sistem melakukan proses:

Application ELF
      |
KlatLoader
      |
Native Runtime
      |
JowoKernel

KlatLoader bertanggung jawab mempersiapkan executable dan dependency yang diperlukan sebelum program mulai berjalan.

Dengan adanya loader sendiri, KLATOS mempunyai execution environment yang terintegrasi dengan runtime sistem.

Runtime Userspace

KLATOS memiliki runtime userspace yang lengkap. Kernel mampu menjalankan executable ELF 64-bit melalui loader internal.

  • ELF Loader
  • Dynamic Linker
  • C Runtime
  • POSIX ABI
  • System Call Interface
  • Process Startup
  • Userspace Memory Manager

Filesystem KLATOS

KLATOS memiliki struktur filesystem yang dirancang sebagai bagian dari platform. Root sistem menggunakan:

/Sistem

Struktur utama:

/Sistem
+-- Program
+-- Perpustakaan
+-- Aplikasi
+-- SumberDaya
+-- Konfigurasi
+-- Data
+-- Pengguna
+-- Runtime

Masing-masing direktori memiliki fungsi yang jelas.

  • /Sistem/Program — berisi program native sistem
  • /Sistem/Perpustakaan — berisi library yang digunakan program
  • /Sistem/Aplikasi — berisi aplikasi yang telah dipasang
  • /Sistem/SumberDaya — berisi resource sistem dan aplikasi
  • /Sistem/Konfigurasi — berisi konfigurasi sistem
  • /Sistem/Data — berisi data sistem
  • /Sistem/Pengguna — berisi environment pengguna
  • /Sistem/Runtime — berisi komponen runtime sistem

Graphics Stack

KLATOS menggunakan graphics stack modern berbasis DRM (Direct Rendering Manager):

  • DRM Device — interface ke GPU melalui /dev/dri/card0
  • Dumb Buffer — framebuffer sederhana tanpa GPU acceleration
  • Framebuffer Management — pengelolaan buffer render
  • Page Flipping — ganti frame tanpa tearing
  • VBlank Synchronization — sinkronisasi dengan refresh rate monitor
  • Zero-copy Framebuffer — sharing buffer antar proses
  • Memory Mapped Graphics — akses framebuffer via mmap
  • Event-driven Rendering — render hanya saat ada perubahan

Kompatibilitas libdrm

Untuk meningkatkan kompatibilitas, KLATOS menyediakan implementasi clean-room dari API libdrm:

// Available API
drmIoctl()
drmModeGetResources()
drmModeCreateDumbBuffer()
drmModeMapDumbBuffer()
drmModeAddFB()
drmModePageFlip()

Aplikasi dapat menggunakan API standar tanpa perlu mengetahui implementasi internal kernel.

Library & Runtime

Aplikasi KLATOS dapat menggunakan library native yang tersedia di:

/Sistem/Perpustakaan

Dependency aplikasi dikelola melalui application platform sehingga runtime aplikasi dapat dipisahkan dari komponen sistem yang tidak diperlukan.

Tujuannya adalah membuat aplikasi lebih terstruktur dan menjaga sistem tetap efisien.

Security Model

Security KLATOS dibangun sebagai bagian dari execution environment. Salah satu konsep penting adalah pembatasan resource aplikasi — aplikasi hanya mendapatkan akses terhadap resource yang diperlukan:

Application
      |
Permissions / Resource Access
      |
Runtime
      |
JowoKernel

KLATOS menggunakan mekanisme seperti pengelolaan keamanan yang kami berinama Klat Security Manager (KSM) untuk membantu membatasi akses aplikasi terhadap sistem. Security regression menjadi bagian dari pengujian setiap perubahan besar.

Selain itu, JowoKernel dirancang dengan fokus pada stabilitas dan isolasi proses:

  • Per-process Virtual Address Space
  • Process Isolation
  • Guard Pages
  • Reference Counting
  • Automatic Resource Cleanup
  • WaitQueue Synchronization
  • Memory Leak Detection
  • Automated Stress Testing

Visi KLATOS

KLATOS ingin menghadirkan sebuah sistem operasi yang:

  • Ringan — menggunakan resource secara efisien dan memisahkan runtime dari kebutuhan development
  • Modern — menyediakan desktop, browser, graphics, developer tools, dan application platform modern
  • Native — memiliki kernel, runtime, filesystem, loader, dan application model yang terintegrasi
  • Aman — security menjadi bagian dari execution model dan diuji sebagai bagian dari setiap perubahan besar
  • Terbuka untuk Developer — developer dapat membangun aplikasi melalui toolchain native dan mendistribusikannya dalam format .kap
